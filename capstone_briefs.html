Predicting Crop Insurance Claim Risk for Kenyan Smallholder Farmers

The Business Problem
An agricultural insurer currently prices smallholder policies using broad county-level averages. A predictive model that identifies individual-farm risk factors could reduce unexpected payout exposure and allow more accurate premium pricing. Your model is the risk engine that makes that possible.
Dataset
crop_insurance_claims.csv
3,000Rows
11Columns
~12%Claim Rate
farmer_idID / string
countycategorical
crop_typecategorical
farm_size_acresfloat
rainfall_received_mmfloat
soil_quality_scoreint (1–10)
fertilizer_usedbinary
years_insuredint
previous_claims_3yrint
distance_to_market_kmfloat
claim_filed ★target / binary
What You Must Build
  • EDA with at least 5 visualisations focused on which features separate claimants from non-claimants
  • Preprocessing pipeline: encode categoricals, scale numerics, handle any class imbalance consciously
  • At least two classifiers: Logistic Regression + one of Random Forest, Decision Tree, or KNN
  • Model comparison using accuracy, precision, recall, and F1-score — and a written argument for which metric matters most here
  • A feature importance or coefficient plot with written interpretation
  • A 200-word underwriting memo presenting findings to a risk committee (not a data science team)
Deliverables
  • Clean, commented Jupyter notebook
  • Underwriting memo as a markdown cell inside the notebook
  • README explaining how to run the notebook

Key Thinking Prompt

In insurance, a false negative means paying a claim you didn't predict. A false positive means flagging a farmer as high-risk when they are not — which affects their premium. Which error is more costly to the business, and how does your choice of model reflect that?

Stretch Goal

Using your model's predicted probabilities, calculate an expected loss per risk segment (multiply predicted probability by a dummy claim payout amount). Rank counties by total expected loss and present the top three as a prioritisation list for the underwriting team.

Veterinary Science  ·  Classification

Predicting Disease Outbreak Risk at Kenyan Livestock Markets

The Business Problem
The Kenya Veterinary Board can only deploy mobile vaccination teams to 30% of county livestock markets in any given month. Your model ranks markets by outbreak risk so deployment decisions are data-driven, not based on who calls the most.
Dataset
livestock_market_outbreak_risk.csv
2,500Rows
11Columns
~32%Outbreak Rate
market_idID / string
countycategorical
seasoncategorical
primary_animal_typecategorical
weekly_animal_throughputint
vaccination_coverage_pctfloat (0–100)
distance_to_water_source_kmfloat
vet_inspections_per_monthint
prev_outbreaks_2yrint
market_density_scoreint (1–10)
outbreak_risk_flag ★target / binary
What You Must Build
  • EDA with at least 5 visualisations — pay particular attention to how season and vaccination coverage interact with the target
  • Preprocessing pipeline with justified encoding and scaling choices
  • At least two classifiers with recall as the primary evaluation metric — explain in writing why missing a true outbreak is the critical failure here
  • A confusion matrix for each model with a plain-English caption: what does each quadrant mean in a veterinary deployment context?
  • A ranked output table: the top 15 highest-risk markets from the test set, formatted as a deployment briefing table
  • A 150-word data gap note: what information would make this model better if you had it?
Deliverables
  • Clean, commented Jupyter notebook
  • Ranked market briefing table exported as a CSV
  • Data gap note as a markdown cell inside the notebook
  • README explaining how to run the notebook

Key Thinking Prompt

With 32% positive cases, this is not a severely imbalanced dataset. But the cost of a false negative (missing a high-risk market) is real — animals die, disease spreads, livelihoods collapse. Does your model reflect that asymmetry in how you've chosen your evaluation metrics and thresholds?

Ranked deployment table — is it formatted for a non-technical user?10

Stretch Goal

Build a composite deployment urgency score: combine the model's predicted outbreak probability with the vaccination coverage gap (100 minus vaccination_coverage_pct) into a single weighted score. Re-rank your top 15 markets using this score and explain whether the ranking changes significantly and why.

Economics  ·  Classification  ·  Credit Risk

Predicting Loan Default in Kenya's Informal Economy

The Business Problem
A Nairobi-based microfinance institution lends to informal sector workers: market traders, boda boda operators, kiosk owners, and jua kali artisans. These borrowers have no formal credit history. Your model scores default risk using alternative data — mobile money behaviour, group lending membership, and repayment track record — without penalising people simply for being unbanked.
Dataset
informal_loan_default.csv
4,000Rows
14Columns
~17%Default Rate
borrower_idID / string
business_typecategorical
loan_purposecategorical
loan_amount_kshfloat
loan_term_monthsint
mpesa_transactions_monthlyint
mpesa_avg_balance_kshfloat — 15% missing
prev_loans_repaidint
prev_loans_defaultedint
group_lending_memberbinary
dependantsint
business_age_monthsint
has_mobile_money_savingsbinary
loan_defaulted ★target / binary
What You Must Build
  • EDA with explicit attention to the missing values in mpesa_avg_balance_ksh — document the pattern and your imputation decision
  • Engineer at least one new feature from existing columns (e.g. loan-to-balance ratio, repayment reliability score)
  • Preprocessing pipeline including encoding, scaling, and missing value handling
  • At least two classifiers with a written argument for which metric matters most in a lending context: precision, recall, or F1
  • A Gini coefficient calculated on your best model's predicted probabilities, with a plain-English interpretation
  • A 200-word policy note: what should the MFI do with borderline borrowers — those scoring between 0.4 and 0.6 probability of default?
Deliverables
  • Clean, commented Jupyter notebook
  • Gini coefficient with plain-English interpretation as a markdown cell
  • Policy note as a markdown cell inside the notebook
  • README explaining how to run the notebook

Key Thinking Prompt

The missing values in mpesa_avg_balance_ksh are not random — informal workers often have inconsistent mobile money usage. Does your imputation method make an assumption about why the data is missing? State it explicitly.

Justify your threshold choices with reference to the business cost of each error type, then show the distribution of borrowers across the three tiers.
